# เขียน spec ให้ agent-factory

เป้าหมายไม่ใช่ "กรอกฟอร์มให้ครบ" แต่คือ **ทำให้ 6 เฟสถัดไปไม่พังเพราะ spec**

spec ถูกแปะเข้าไปในทุก prompt ของทุกเฟส ทุก retry — ประโยคที่กำกวม 1 บรรทัด
ถูกจ่ายซ้ำหลายสิบครั้ง และทำให้แต่ละเฟสตีความไม่ตรงกัน

## ลำดับ

1. **อ่านของที่มีก่อนถาม** — `specs/_template.md` (โครง) และ `specs/minicat.md`
   (ตัวอย่างที่รันผ่านจริงมาแล้ว) อย่าถามสิ่งที่อ่านเอาได้
2. **สัมภาษณ์** ตามหัวข้อข้างล่าง ถามเป็นชุด ไม่ใช่ทีละคำถาม
3. **ทวนกลับพร้อมข้อเสนอปรับปรุง** — ไม่ใช่จดตามอย่างเดียว (ดู "ช่วยคิด")
4. **เขียนไฟล์** `specs/<ชื่อ>.md`
5. **ตรวจฟรี**: `./tools/spec-lint.sh specs/<ชื่อ>.md` แก้จนผ่าน
6. บอกคำสั่งรันจริง แล้ว**หยุด** — การรันคือการตัดสินใจใช้โควตา ไม่ใช่ขั้นตอนต่อเนื่อง

## สัมภาษณ์ — ถามเท่าที่ยังไม่รู้

| # | ถามอะไร | ถ้าตอบคลุมเครือ ให้ดันต่อว่า |
|---|---|---|
| 1 | ใครเข้ามา ทำอะไร ได้อะไรกลับไป | "คนที่เข้ามาครั้งแรกเห็นอะไรก่อน" |
| 2 | มีหน้าอะไรบ้าง หน้าไหนต้องล็อกอิน | "แล้วหน้าที่คนนอกห้ามเห็นล่ะ" |
| 3 | เก็บข้อมูลอะไร ฟิลด์อะไร อันไหนบังคับ | "ฟิลด์นี้ว่างได้ไหม ถ้าว่างหน้าเว็บแสดงอะไร" |
| 4 | ใครล็อกอินได้ สร้างบัญชียังไง | "มีหน้าสมัครไหม หรือเจ้าของสร้างให้อย่างเดียว" |
| 5 | "เสร็จ" คือทำอะไรได้ — เป็นขั้นตอนที่คนเดินตามได้ | "ข้อนี้จะรู้ได้ยังไงว่าผ่าน กดตรงไหน เห็นอะไร" |
| 7 | อะไรที่**ไม่**ต้องทำ | "ตะกร้า? ชำระเงิน? หลายภาษา? อีเมล?" |
| 8 | ต้องต่อ API ข้างนอกไหม | "ชื่อตัวแปร env พอ **ห้ามบอกค่าจริง**" |
| 9 | ขึ้น local หรือ VPS มีโดเมนยัง | |

หัวข้อ 6 (สี/โทน) ไม่ตอบก็ได้ — ไม่ใช่ของบังคับ

## ช่วยคิด — สิ่งที่ต้องทักท้วง ไม่ใช่จดตาม

**ก) ข้อ 5 ที่ตรวจไม่ได้** = ปัญหาที่แพงที่สุด
เฟส 40 เอาข้อ 5 ไปเดินจริงแล้วยิง curl ถ้าเขียนว่า "ใช้งานง่าย" หรือ "เร็ว"
gate ตรวจไม่ได้ ต้องแปลงเป็นขั้นตอน: เปิดหน้าไหน → กดอะไร → ต้องเห็นอะไร / ได้ HTTP อะไร

**ข) ข้อ 7 ว่าง = โปรเจคบวมแน่นอน**
ถ้าเจ้าของบอก "ไม่รู้จะห้ามอะไร" ให้เสนอรายการมาตรฐานให้ตัด:
ตะกร้า · ชำระเงิน · สมัครสมาชิกเอง · หลายภาษา · ส่งอีเมล · แจ้งเตือน · ค้นหาขั้นสูง · รายงาน/สถิติ

**ค) ของที่ spec มักลืม แล้วไปโผล่เป็นบั๊กทีหลัง**
- หน้าที่ต้องล็อกอิน **ตอนยังไม่ล็อกอินต้องเจออะไร** (เด้งไป `/login` หรือ 404)
- URL ที่ไม่มีจริง (`/products/9999`) ต้องได้ 404 ไม่ใช่พัง
- อัปรูป: จำกัดขนาด/จำนวนไหม แสดงสัดส่วนไหน
- ข้อมูลตั้งต้น (seed): เปิดเว็บครั้งแรกหน้าโล่งหรือมีตัวอย่าง
- ใครลบข้อมูลได้ ลบแล้วของที่อ้างถึงมันเป็นยังไง

**ง) ขอบเขตที่ใหญ่เกินหนึ่งรอบ**
ถ้านับหน้าได้เกิน ~10 หรือมีตารางเกิน ~6 ให้เสนอตัดเป็นรอบแรกที่เล็กกว่า
แล้วบอกตรงๆ ว่าอะไรถูกเลื่อน — pipeline นี้ยังไม่เคยพิสูจน์กับของขนาดนั้น

**จ) ห้ามแตะ Stack**
ท้าย template ล็อก stack ไว้แล้ว (Next.js 16 · SQLite · NextAuth v5 · Docker+Caddy)
พร้อม gotcha ที่เคยทำพังจริง (`proxy.ts` ต้องอยู่ root · `bcryptjs` ใน
`serverExternalPackages` · better-sqlite3 v12 · base image `node:22-bookworm-slim`)
ถ้าเจ้าของอยากได้อย่างอื่น = งานคนละแบบ ไม่ใช่ spec คนละไฟล์ — บอกให้ชัด

## เขียนไฟล์

- ก๊อปโครงจาก `specs/_template.md` **ลบคอมเมนต์สอนวิธีกรอกออกให้หมด** และห้ามเหลือ
  ตัวยึดที่ยังไม่ได้แทน (`<ชื่อตาราง`, `/xxx`, `<ชื่อโปรเจค>`)
- เนื้อหาเป็นไทยได้ แต่ **ชื่อไฟล์ ตาราง ฟิลด์ ตัวแปร เป็นอังกฤษ**
- ⛔ **ห้ามใส่ค่า key/token/รหัสผ่านจริง** เขียนแค่ชื่อตัวแปร ค่าจริงไปอยู่ `.env`
  (spec ถูกแปะในทุก prompt ทุก retry = ความลับจะไปอยู่ในทุก log)
- เขียนสั้นและตรง ทุกบรรทัดถูกส่งซ้ำทุกเฟส

## ตรวจก่อนจบ

```bash
./tools/spec-lint.sh specs/<ชื่อ>.md
```

อ่านไฟล์อย่างเดียว ไม่เรียกโมเดล ไม่กินโควตา — แก้จน exit 0
lint บอกได้แค่ว่า "กรอกครบไหม" **ไม่ได้บอกว่าเนื้อหาดีไหม** ส่วนนั้นคืองานข้อ "ช่วยคิด"

จบแล้วบอกคำสั่ง แล้วปล่อยให้เจ้าของเป็นคนกด:

```bash
./factory.sh specs/<ชื่อ>.md --name <ชื่อ>
```
