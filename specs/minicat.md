# minicat

เว็บทดสอบ pipeline — เล็กที่สุดที่ยังกินทุกกลไก (DB, auth, route ที่ต้องล็อกอิน, dynamic route, อัปโหลดรูป, seed)

---

## 1. [บังคับ] เว็บนี้คืออะไร ใครใช้

แคตตาล็อกสินค้าเล็ก ๆ ของร้านเดียว ลูกค้าเข้ามาดูรายการสินค้าและกดเข้าไปดูรายละเอียดทีละชิ้น
เจ้าของร้านล็อกอินหลังบ้านเพื่อเพิ่ม แก้ ลบสินค้า และอัปโหลดรูปสินค้าได้ชิ้นละ 1 รูป
ไม่มีการสั่งซื้อ ไม่มีตะกร้า ลูกค้าดูอย่างเดียว

## 2. [บังคับ] หน้าเว็บทั้งหมด

| path | สาธารณะ/ต้องล็อกอิน | เนื้อหา |
|---|---|---|
| `/` | สาธารณะ | รายการสินค้าทั้งหมด เรียงใหม่สุดก่อน แต่ละชิ้นแสดงรูป ชื่อ ราคา กดแล้วไปหน้ารายละเอียด |
| `/products/[id]` | สาธารณะ | รูป ชื่อ ราคา รายละเอียด ของสินค้าชิ้นนั้น · ถ้า id ไม่มีอยู่จริงให้ตอบ 404 |
| `/login` | สาธารณะ | ฟอร์มอีเมล+รหัสผ่าน ล็อกอินสำเร็จเด้งไป `/admin` ผิดให้ขึ้นข้อความ error ในหน้าเดิม |
| `/admin` | ต้องล็อกอิน | ตารางสินค้าทั้งหมด มีปุ่มเพิ่ม แก้ ลบ · ยังไม่ล็อกอินให้เด้งไป `/login` |
| `/admin/products/new` | ต้องล็อกอิน | ฟอร์มสร้างสินค้า (ชื่อ ราคา รายละเอียด รูป) |
| `/admin/products/[id]/edit` | ต้องล็อกอิน | ฟอร์มเดียวกันแต่กรอกค่าเดิมไว้ · มีปุ่มลบ |

## 4. [บังคับ] ใครล็อกอินได้ ทำอะไรได้

admin คนเดียว (เจ้าของร้าน) ไม่มีหน้าสมัครสมาชิก
บัญชีสร้างจาก `npm run seed` เท่านั้น: `admin@minicat.local` / `minicat1234`
ล็อกอินแล้วเพิ่ม แก้ ลบสินค้า และอัปโหลดรูปได้
ทุก path ที่ขึ้นต้น `/admin` ต้องถูก protect ที่ middleware ไม่ใช่เช็คในแต่ละหน้า

## 5. [บังคับ] "เสร็จ" คือทำอะไรได้บ้าง

1. เปิด `/` เห็นสินค้าจาก seed อย่างน้อย 3 ชิ้น แต่ละชิ้นมีชื่อกับราคา
2. คลิกสินค้าชิ้นแรก → เข้า `/products/1` เห็นชื่อ ราคา รายละเอียด รูป
3. เปิด `/products/9999` (ไม่มีอยู่จริง) → ได้ 404
4. เปิด `/admin` โดยไม่ล็อกอิน → ถูกเด้งไป `/login`
5. ล็อกอินด้วย `admin@minicat.local` / `minicat1234` → เข้า `/admin` ได้ เห็นตารางสินค้า
6. กดเพิ่มสินค้า กรอกชื่อ+ราคา+อัปโหลดรูป 1 ไฟล์ → บันทึกแล้วกลับไป `/` เห็นสินค้าใหม่อยู่บนสุดพร้อมรูปที่อัป
7. แก้ราคาสินค้าชิ้นเดิม → `/products/<id>` แสดงราคาใหม่
8. ลบสินค้าชิ้นนั้น → หายจาก `/` และ `/products/<id>` ตอบ 404

- ภาษา: ไทย

## 7. สิ่งที่ **ไม่** ต้องทำ

- ไม่ต้องมีตะกร้า ชำระเงิน หรือระบบสั่งซื้อ
- ไม่ต้องมีหน้าสมัครสมาชิก ลืมรหัสผ่าน หรือเปลี่ยนรหัสผ่าน
- ไม่ต้องมีหลายภาษา
- ไม่ต้องส่งอีเมลหรือแจ้งเตือน
- ไม่ต้องมีหมวดหมู่ แท็ก ค้นหา หรือแบ่งหน้า
- ไม่ต้องมีรูปมากกว่า 1 รูปต่อสินค้า
- ไม่ต้องเขียนเทสต์อัตโนมัติ — gate เป็นตัวตรวจ

## Stack (ล็อกไว้แล้ว ไม่ต้องแก้)

Next.js 16 (App Router) · TypeScript · Tailwind · SQLite (better-sqlite3, raw SQL)
NextAuth v5 credentials + bcryptjs · รูปเก็บ local disk + sharp บีบตอนอัป
Docker Compose (web + caddy) · migration เป็น .sql + PRAGMA user_version

**Gotchas ที่ต้องทำตาม** (เจอมาแล้วจริงจาก livincolor):
- middleware ต้องเป็น `proxy.ts` ที่ **root** ไม่ใช่ใน `src/` — ไม่งั้น Turbopack dev ไม่รัน = route ไม่ถูก protect
- `bcryptjs` ต้องอยู่ใน `serverExternalPackages` ของ next.config
- `better-sqlite3` ใช้ v12 (prebuilt สำหรับ node 24)
- Docker base image: `node:22-bookworm-slim`
